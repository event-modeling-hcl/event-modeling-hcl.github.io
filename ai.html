Using .em.hcl with coding agents

A coding agent can draft .em.hcl, run the validator, fix diagnostics, and render the result.

This creates a useful feedback loop.

Works today

1. Draft

Describe the events, actors, ownership, and workflow.

2. Validate

Run emhcl fmt -w, then emhcl validate.

3. Fix

Use the source position and EMxxx diagnostic.

4. Diagram

Render the model and review its causal shape.

5. Review

A person checks whether it describes the business.

Validation catches language and model-structure errors. The default valid profile permits modeling warnings. Even strict validation does not prove that a model follows the method or describes the business correctly.

Give the agent Specification v0.8.0 for syntax and the methodology guide for human review. The methodology is conceptual, not another grammar. Do not invent query, storyline, note, linked_copy, or translation blocks. A translation is an automation that consumes an event of an external = true bounded context. Field mapping records metadata, not executable lineage checks. Do not add a mapping to a new model.

Specification v0.8.0 has blocks for facts that agents used to write in descriptions or comments: lifecycle, field_source, evidence, decision, aggregate identity, and dispatch assertions. Tell the agent to use one only when the business states the fact. A fact that the agent invents to fill a checklist is not evidence. See Method facts.

Use the agent skills

The Event Modeling HCL plugin holds the event-modeling-hcl language skill and 32 method skills. The language skill moved there from the tool repository. Install the plugin in Claude, Codex, or ChatGPT, or copy the skill folder plugins/emhcl-skills/skills/event-modeling-hcl to your coding agent. The skill teaches specification v0.8.0. It needs emhcl v0.17.0 or newer, because older releases implement older specification versions. Its front matter states these facts in metadata.spec_version and metadata.emhcl_min. To see the versions that a binary implements, run emhcl version --format json.

The skill runs three gates in this order. A gate passes only when its command exits with code 0. If a gate fails, the gates after it do not run. After each edit, start again at the first gate.

emhcl fmt -w model.em.hcl # 1. formatted emhcl validate model.em.hcl # 2. valid: a workshop draft is done here emhcl validate --profile strict model.em.hcl # 3. implementation-ready

The strict profile fails on an open hotspot (EM406) and on a command without a reason (EM404). Do not let the agent invent a business rule to make strict pass. Keep the hotspot and call the model a workshop draft. For CI and scripts, emhcl validate --format json writes the diagnostics as one JSON object. emhcl fmt --check reports files that need formatting and changes no file.

For a folder model, validate the folder, not each file in isolation. Use the diagnostic's file, line, column, and code to fix the source. Keep whole blocks intact. Put each block in any member file: file names and block positions do not change the model. emhcl fmt -w on the folder formats each member file.

Workflow status records progress: created, planned, assigned, in_progress, review, blocked, done, or informational. A status is not a validator verdict. Do not mark a workflow done only because validation passes.

To let each person on a team change a shared model through the agent, use the collaboration procedures of the plugin. em-change turns a request in plain words into a merge request. em-review validates a merge request and comments on it. See the plugin page.

Prompt examples

  • Draft a model Here are the business Events for {domain}: {list}. Use the event-modeling-hcl agent skill to draft a .em.hcl model for Specification v0.8.0. Put every story workflow on the board. Give every field a type. Choose a workflow pattern for each slice and add native scenarios. Run emhcl fmt -w, then emhcl validate on the whole model. Report warnings, assumptions, and open business questions for human review.
  • Fix a validator error emhcl validate produced this diagnostic: {diagnostic}. Fix the model without changing the intended business behavior.
  • Implement one workflow Here is one validated .em.hcl workflow: {workflow}. Implement its {command handler / projection / endpoint} in {language}. State any assumptions.
