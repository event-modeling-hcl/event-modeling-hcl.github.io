One format choice

Why HCL?

The project needed a text format that people can edit by hand and a tool can validate.

JSON is easy to validate but noisy to write. YAML is pleasant to write. HCL has one more feature: domain concepts can be blocks.

The project chose HCL for this experiment.

{ "kind": "event", "name": "student_registered" } kind: event name: student_registered event "student_registered" { }

In this project, the block form helps because the source looks like the concepts that people discuss.

References and validation

event.school.student_registered

HCL parses this as a traversal expression. HCL does not know that it refers to an Event.

The .em.hcl validator supplies that meaning. It checks the reference kind, scope, and existence. Then it produces a typed model for the formatter, renderer, and other tools.

These formats solve different problems. This table lists the differences that matter for this project.
